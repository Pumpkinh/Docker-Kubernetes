# Docker-Kubernetes
# Docker Multi-Stage Build with Three.js + NGINX

## Опис проєкту

Цей проєкт демонструє приклад багатоступеневої збірки Docker-образу (`multi-stage build`) для статичного вебзастосунку на базі `Three.js`.

У проєкті реалізовано:
- автоматичну збірку фронтенд-застосунку всередині Docker build
- використання `multi-stage Dockerfile`
- копіювання результатів збірки у фінальний образ з `nginx`
- запуск `nginx` від окремого non-root користувача
- можливість обирати одну з кількох анімацій через shell-скрипт

---

## Логіка роботи

### 1. Build stage

На першому етапі використовується базовий образ з Node.js.

Усередині цього етапу виконується:
1. автоматичне створення шаблону Vite-проєкту
2. встановлення бібліотеки `three`
3. копіювання вибраного файлу анімації у проєкт як `src/main.js`
4. копіювання `index.html`
5. запуск production-збірки командою `npm run build`

У результаті формується каталог:


/app/dist


У ньому знаходяться готові статичні файли:

index.html
JavaScript bundle
додаткові assets


### 2. Runtime stage

На другому етапі використовується легкий образ nginx:alpine.

У цей stage копіюються результати збірки з першого етапу:

вміст каталогу /app/dist
власний конфігураційний файл nginx.conf

Також у фінальному образі:

створюється окремий користувач
надаються права доступу до необхідних директорій
nginx запускається не від root, а від створеного користувача
Чому використовується multi-stage build

Підхід multi-stage дозволяє розділити процес на дві незалежні частини:

фінальний образ менший за розміром
у runtime-образі немає зайвих build-залежностей
структура ближча до production practice
краща безпека


### Чому nginx запускається від окремого користувача

За замовчуванням багато контейнерів запускаються від root, але це не є бажаною практикою з точки зору безпеки.

У цьому проєкті:

створюється окремий користувач
nginx запускається від нього
порт змінено на 8080, оскільки non-root процес не може слухати привілейований порт 80
PID-файл і тимчасові директорії винесені у /tmp, щоб non-root користувач мав права на запис

Це дозволяє реалізувати більш безпечний варіант запуску контейнера.

### Варіанти анімацій

Проєкт підтримує кілька варіантів main.js, які можна підставляти під час збірки образу.

Приклади анімацій:

Galaxy
Particles
Solar System
Cyberpunk Grid
Black Hole
Starfield Warp

Під час Docker build потрібний файл копіюється у контейнер під ім’ям:

/app/src/main.js

Таким чином один і той самий Dockerfile можна використовувати для збірки різних візуалізацій.

### Shell-скрипт run.sh

Для зручності створено інтерактивний shell-скрипт run.sh.

Його задача:

показати користувачу список доступних анімацій
отримати вибір
підставити відповідний файл через --build-arg
запустити docker build

Це дозволяє не редагувати Dockerfile вручну при кожній новій збірці.

### Загальна схема роботи
run.sh
   ↓
вибір анімації
   ↓
docker build --build-arg MAIN_FILE=...
   ↓
Stage 1:
  Node.js + Vite + Three.js
  npm run build
   ↓
отримання /app/dist
   ↓
Stage 2:
  nginx + non-root user
  копіювання dist у /usr/share/nginx/html
   ↓
готовий runtime image
Як зібрати образ
Через shell-скрипт
./build.sh
Або вручну
docker build --build-arg MAIN_FILE=main3.js -t solarsystem:1 .
Як запустити контейнер
docker run -p 8080:8080 solarsystem:1

Після запуску застосунок буде доступний у браузері за адресою:

http://<host>:8080
